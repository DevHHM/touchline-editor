# Touchline 자동 업데이트

0.13.0부터 프로그램 시작 후 공식 공개 저장소 `DevHHM/touchline-editor`의 릴리스를 백그라운드에서 확인합니다. 로그인이나 GitHub 토큰은 사용하지 않습니다. 업데이트 확인 실패나 인터넷 연결 끊김은 에디터 사용을 막지 않습니다. 이전 0.12.x 실행본에는 자동 업데이트가 없으므로 최초 한 번은 0.13.0 이상 ZIP 전체를 새 폴더에 압축 해제해야 합니다.

`업데이트`에서 자동 확인을 끄거나 `지금 확인`을 누를 수 있습니다. 기본은 정식 릴리스입니다. GitHub에서 Pre-release로 표시된 공개 테스트판을 받으려면 `테스트 릴리스 포함`을 선택하세요. 같은 버전이나 이전 버전으로는 자동 변경하지 않습니다.

새 버전 알림에서 동의하면 ZIP을 내려받아 SHA256과 패키지 내부의 모든 파일을 검증합니다. 거절하면 자동 알림을 하루 미룹니다. 다운로드 중에도 현재 작업을 계속할 수 있습니다. 검증이 끝나면 **에디터를 정상 종료한 뒤 설치**하도록 예약됩니다. `설치 예약 취소`로 취소할 수 있습니다. 자동 종료·자동 재시작·게임 조작은 하지 않습니다. 적용하지 않은 변경 내용에 대한 기존 종료 확인도 그대로 진행됩니다. 다운로드 도중 종료하면 설치하지 않습니다.

설치는 해당 배포 폴더만 바꿉니다. `%LOCALAPPDATA%/TouchlineEditor`의 설정과 이력은 그대로 남으며, 배포 폴더에 사용자가 추가한 파일도 새 폴더로 복사합니다. 새 패키지 파일과 개인 파일이 충돌하거나 다른 에디터/로컬 API가 해당 배포본을 사용 중이면 설치를 중단합니다. 그 프로세스를 강제로 종료하지 않습니다. 쓰기 권한이 없는 폴더에서는 자동 설치가 실패하므로 사용자에게 쓰기 권한이 있는 폴더에 ZIP을 압축 해제하세요.

기존 배포본 전체는 같은 상위 폴더의 `배포폴더이름.backup-날짜-식별자`에 남습니다. 교체 도중 오류가 발생하면 이전 폴더로 되돌립니다. 설치 결과는 다음 에디터 시작 시 업데이트 화면에 표시되며 `%LOCALAPPDATA%/TouchlineEditor/Updates/last-result.json` 또는 `last-result.json.read`에도 남습니다. 다운로드와 검증용 임시 파일은 `Updates/job-…`에 보관됩니다. 에디터와 설치 도우미가 모두 종료된 뒤 불필요한 job 폴더를 삭제할 수 있습니다.

정전처럼 프로세스가 강제로 끝나면 상위 폴더에 `.배포폴더이름.update-transaction.json`이 남을 수 있습니다. 이 경우 자동 업데이트는 더 진행하지 않습니다. 다음 순서로 복구하세요.

1. Touchline 에디터와 해당 배포본의 로컬 API를 모두 종료합니다. transaction 파일을 메모장으로 열고 `target`(원래 폴더), `backup`(이전 버전), `incoming`(새 버전 임시 폴더) 경로를 확인합니다.
2. `backup`이 있으면 그 안에 `Touchline Editor.exe`, `app`, `engine`, `package-manifest.json`이 있는지 확인합니다. `target`이 없으면 `backup` 폴더를 원래 `target` 이름으로 바꿉니다. `target`이 이미 있으면 먼저 그 폴더를 `.interrupted` 등의 별도 이름으로 보관한 다음, `backup`을 원래 이름으로 바꿉니다. 개인 파일이 있을 수 있으므로 어느 폴더도 바로 삭제하지 마세요.
3. `backup`이 없고 원래 `target`이 온전하면 교체 시작 전에 중단된 것입니다. `target`을 유지합니다. `target`과 `backup`이 둘 다 없으면 `incoming`을 실행하지 말고 공식 배포 ZIP 전체를 새 폴더에 압축 해제하세요.
4. 복구한 `target`에서 `docs/Verify-Package.ps1`로 검사하고 에디터가 열리는 것을 확인합니다. 그 후에만 transaction 파일을 삭제하세요. 남은 `incoming`이나 `.interrupted` 폴더는 필요한 개인 파일이 없는지 확인한 뒤 정리합니다. 백업은 자동 삭제하지 않습니다.

릴리스 주소와 다운로드 리디렉션은 공식 GitHub 호스트로 제한합니다. ZIP 경로 이동, 링크, 중복 경로, 과도한 압축 해제 크기, 버전/파일 목록/SHA256 불일치를 거부합니다. SHA256은 공식 저장소에서 공개한 파일과 내려받은 파일의 일치를 확인하며 별도의 코드 서명이나 독립적인 배포자 서명을 대신하지 않습니다.
