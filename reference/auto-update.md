# Portable update contract

The native WPF client checks the public GitHub releases API for `DevHHM/touchline-editor`, without authentication. The canonical repository was established by the prior public-release verification. The API contract is documented at https://docs.github.com/en/rest/releases/releases . The stable channel excludes drafts and prereleases; preview inclusion is explicit. Only numeric `vMAJOR.MINOR.PATCH` tags greater than the executing assembly version qualify. Feed order never drives version comparison.

A release must publish both `Touchline-Editor-VERSION-win-x64.zip` and `.zip.sha256`, using those exact names and the exact repository/tag download path. `build-wpf.ps1` builds the independent self-contained single-file helper, includes it in `app/`, runs its no-op `--helper-check`, and `tools/package-wpf.ps1` emits the manifest, ZIP and SHA256. Publish the ZIP **and its checksum asset** together; an incomplete release is not offered. Publishing remains a separate user-authorized action. Never replace assets of an existing version; use a new version.

`InitializeUpdates()` attaches non-blocking startup work, skips UI-check runs and supports `--no-update true`. `OpenUpdateSettings()` exposes manual check, channel, preference, and cancellation controls. `LaunchPendingUpdate()` must be called only after the normal close guards and all bridge/tool disposal, immediately before final window close. Downloading or checking never authorizes installation: a user must accept the offer, the whole archive must pass verification, and the normal application shutdown must complete.

The client restricts API calls to its compiled public endpoint and initial asset links to the exact repository/tag. Redirects are handled explicitly and restricted to GitHub's release-asset hosts. Requests contain no authorization header, cookies or default credentials. Downloads enforce advertised size and a 1 GiB ceiling, compare the SHA256 sidecar and GitHub asset digest when present, and stream to a partial file. ZIP extraction validates all paths before writing and rejects traversal, Windows special paths, links, duplicate case-folded paths, over 20,000 entries and more than 4 GiB expanded. Manifest validation enforces package layout, version, target, required executables/runtime files, sizes, hashes and absence of extra package files.

On normal exit the existing helper is copied outside the install directory and receives a local JSON request. It waits for the exact parent PID/start time without killing it, permits the portable launcher to exit, verifies the archive again, then copies a validated incoming package beside the destination. Untracked user files are preserved; collisions abort. Exclusive executable checks reject an active second editor or API. An exclusive installation lock prevents concurrent installers. Two directory renames retain the full old package as a backup; caught failures restore it. A transaction record remains if recovery cannot finish or the process/power is interrupted. No restart is automatic. The helper never calls the game or local API.

`dotnet run --project desktop/Touchline.UpdaterTests --configuration Release` runs offline fixture tests for version/channel selection, trusted URL/checksum validation, bounded download corruption, hostile redirects, traversal/links/duplicates, manifest integrity, locked files, preserved user data, retained backups and failure injection before/after both directory moves. The WPF and helper link the same implementation files, preventing a different installer implementation from escaping these tests.

Limitations: this is a portable updater, not a Windows installer/service; it does not elevate, register an uninstall entry, modify protected folders, sign code or automatically repair after power loss. Checksums obtained from the same trusted repository establish integrity, not independent publisher authenticity. Reparse-point install paths are intentionally rejected. Download caches and backups remain until the user removes them. Local API processes must be stopped before applying an update to their package.
